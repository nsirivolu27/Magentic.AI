The brief
Problem

Chat tools leave the chain of custody to the person

In federal delivery an AI output is usable only when you can show where it came from, who reviewed it, and that nothing changed afterwards.

Constraint

Nothing advances, publishes or trains on its own

A single owner cannot approve their own stage. A changed output invalidates every signature on it. Every limit the page shows is enforced again on the server.

Answer

Put the chain in the software

An agent drafts a stage, the evidence sits beside the draft, a person edits, an independent reviewer signs. It runs on a laptop with a local model or on a company server with tenants.

What a person can do today

Eight working areas, each with a test behind it

Workflows

Start a run and see, per run, the stage, the owner, the output state and the one next action.

Output review

Evidence, original output, edited handoff and approval state in one grid. The evidence names each source as read, empty or missing.

Approval gates

Independent signatures over a content hash. Owner and author can never approve their own stage.

Agent Studio

Build an agent, grant read only tools with limits, save tests bound to its version, assign to a stage only after a pass. The server answers 409 otherwise.

Model Studio

Train, evaluate, approve and assign an assistant through six guided stages.

Ontology and Zenfluence

Ingest a public dataset into Ontology objects with lineage, or attach a reviewed, hashed snapshot of a Jira ticket or Confluence page. Read only.

Windows application

Installer with a SHA256 manifest, Apps and features entry, uninstaller that keeps data, update feed check.

MCP server

The same operations for any MCP client, scoped to one workspace, with read only annotations on every tool.

Rules the server enforces

Shown on the page, refused on the server

  1. 01Every API call is checked for current membership of the workspace it names.
  2. 02An agent that must read a source and does not is failed; the evidence block lists each file as read, empty or missing.
  3. 03Approvals sign a content hash. Change the content and the signatures stop counting.
  4. 04An agent version with no passing test cannot be assigned to a stage.
  5. 05Credentials are setting names in configuration, never values. Nothing echoes a key to a page or a log.
  6. 06Outbound reads are https only, size capped, time capped, redirects refused, and checked against what was asked for.
How it is built

One process, one loopback port, files on disk

Files, not a database

A workspace is a folder of JSON with a storage version and atomic writes. The Windows package is a bundled runtime and a browser window.

Schemas at every boundary

Request bodies, stored documents and configuration files are parsed with zod. A file written by a newer version is refused with a message, never rewritten in silence.

Views as functions

Pages return HTML strings, so a view test renders a page for owner, reviewer and viewer and asserts on the words each one may see.

Honest states

Every page shows loading, empty, error, not connected, not assigned, blocked and awaiting approval, each with the one step that resolves it.

How the work is run

Every change takes the same path

BriefA Jira story with goal, routes touched, constraints and acceptance criteria.
PlanFiles, tests to add and risks, written on the story before code.
BuildIn an isolated copy of the tree. New tests only; existing tests are never edited to pass.
VerifyTypecheck, test, build and build:workbench, with counts recorded.
Diff reviewThe patch is attached to the story before anything is applied.
ApplyEvery target file's hash is checked before the write and after it.
Verify on WindowsThe same four scripts on the target machine, counts recorded separately.
Look at itAt 1440 and 360 px, keyboard order, measured contrast, screenshots on the story.

Seven delivery epics and forty stories carry that trail. Decisions that need a product owner are their own tickets with the options written out, so nothing blocks in silence.

Verify it in ten minutes

Run it and try three things

corepack enable
corepack pnpm install --frozen-lockfile
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
corepack pnpm build:workbench
node .\workbench\dev.mjs --port=4182

Then open http://127.0.0.1:4182

1. Open a run on Workflows. The evidence block names every source as read, empty or missing, and the approval block shows who may sign and who may not.

2. In Agent Studio, change a tested agent and try to assign it. The control is disabled and the API answers 409.

3. Stop Ollama and open Chat. You get the setup steps, not an error.
