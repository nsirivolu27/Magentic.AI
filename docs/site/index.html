Who it is for

Teams that are allowed to use AI only if they can show their work

The lead

Answer "where did this come from" in one click

Open any run and see the sources the agent read, the tools it called, who edited the handoff and who signed it. No digging through chat history.

The reviewer

Read the draft next to its evidence

The original output, the edited handoff and the evidence sit in one grid. Sign when it is right. If anyone changes the output afterwards, your signature stops counting.

The builder

Trust an agent only after it passes a test

Give an agent read only tools with limits, write a test case, run it. An agent that has not passed on its current version cannot be put on a stage.

How it works

The handoff is a controlled boundary.

A workflow is a sequence of stages such as intake, discovery, design, build, review and release. Gated stages require the configured independent approvals; ungated stages follow their own completion policy.

What you get

The whole loop, from draft to signed release

Workflows

Every run on one page: the stage it is on, who owns it, the state of its output and the one next action. Blocked, waiting and done look different at a glance.

Output review

Evidence, original output, your edits and the approval state side by side. The evidence names each source as read, empty or missing, so a confident draft built on nothing is caught.

Approval gates

Independent reviewers sign a hash of the content. The owner and the author can never approve their own stage, on a laptop or on a company server.

Agent Studio

Build agents from honest templates, grant tools with call budgets and timeouts, save tests bound to the agent version, and record execution, checks and human review as three separate facts.

Model Studio

Configure training, evaluate a candidate, review a release and assign an assistant. The development provider creates labeled placeholder artifacts, not trained model weights.

Connectors

Attach a reviewed, hashed snapshot of a Jira ticket, a Confluence page or an Ontology dataset to a run. Evidence reads are separate from explicitly configured actions such as Jira updates, Slack messages and reviewed Lambda invocation.

Chat

Talk to a local Ollama model or your own provider key. The first run tells you what to set up instead of failing.

MCP for your tools

The same workflow operations are available to any MCP client, scoped to one workspace, with the same rules enforced.

Multiple ways to work.

The browser presents state. The server decides what may happen. MCP clients reach the same workspace engines through scoped tools.

Follow a real request through the code
  1. browser.ts renders the workspace and submits an action to the HTTP API.
  2. server.ts resolves identity, verifies workspace membership and validates the payload.
  3. pipeline.ts checks the run revision, stage, role and approval rules before updating state.
  4. scheduler.ts and stage-agent.ts execute approved assistant stages using their granted MCP tools.
  5. storage.ts persists workspace state. Drafts, evidence and content hashes remain available for review.
Why teams can trust it

The rules live on the server, not in the interface

  1. 01Nobody approves their own work. Owner and author are locked out of their own gate.
  2. 02Change an approved output and every signature on it is void. Review again or ship nothing.
  3. 03An agent that was told to read a source and did not is failed, with the missing file named.
  4. 04An agent version with no passing test cannot be assigned to a stage.
  5. 05Credentials stay behind server-side settings or the configured encrypted connection vault. They are not part of the workflow evidence.
  6. 06Outbound reads are https only, size capped, time capped, and checked against what was asked for.

Questions

Straight answers

Does it send my documents anywhere?

Model requests and configured external actions can send selected content outside the workspace. Review references, provider settings and message previews before sending.

Can an agent publish or deploy on its own?

Agents do not receive blanket deployment rights. Approval gates and integration permissions are checked by the backend; configured external actions are separate from drafting.

Which models work?

Installed Ollama models and supported provider integrations with valid credentials. Saved connections use server-side settings or the encrypted vault. Provider availability must be tested.

What happens when something is not set up?

You get the setup steps on the page. Not connected, not assigned, blocked and waiting each show the one action that resolves them.

Current limits

  • This website simulates the journey; it is not an authenticated workspace.
  • Model completion and token counts do not establish answer accuracy. Review the cited evidence.
  • Company repository execution needs isolated workers before it can be enabled.
  • File-backed company storage assumes one writer. Hosted scale, backup and recovery need further work.
  • Clerk, Stripe, Slack, Jira, Lambda and Foundry require real configuration. This page connects none of them.
  • No claim of federal authorization, accreditation or production readiness.
