# Workforce agent catalogue — Accenture-inspired

This is an illustrative public capability map plus proposed reusable agents. It is not Accenture's internal reporting chart, a complete subsidiary/employee inventory, or an endorsed product. Public business labels are sourced; all agent roles and their assignments are Magentic design proposals.

## Explore

Open `index.html` locally. Expand a branch, select an agent, inspect its grounding, tool grants, human reviewer and test expectations. Search filters the proposed roles. The map is self-contained and makes no network requests.

The company has multiple independent dimensions: capabilities, industries and geographic markets. These are not a single reporting tree, nor do parent nodes grant access. Internal enablement and federal delivery are explicitly proposed overlays.

## Use a base agent

1. Choose a role and download its definition, or open the matching file in `agents/`.
2. In Magentic Agent Studio, use **Import an agent** and paste that single JSON definition. Do not paste the full catalogue envelope.
3. Choose an actually connected model; `select-connected-model` is a placeholder, never a working provider.
4. Attach an authorized repository containing the relevant source exports. Set the client/workspace and data classification before supplying documents. Imported agents cannot fetch enterprise sources.
5. Review tools and limits. Required source reading is enabled. A read proves access, not answer correctness. Validator roles also need a configured validation command.
6. Prepare synthetic fixtures for the listed test cases, run them, and record independent quality review. Test cases in this pack have NOT been run against a model.
7. Assign the saved agent to a workflow; retain existing independent review gates. No template is installed, approved, published or auto-assigned by opening this map.

The current workspace limit is 30 saved configurations; this pack contains 26. Import only the roles needed, accounting for configurations already saved. Models and sources are chosen per workspace rather than encoded as corporate accounts.

## Catalogue contract

`catalogue.json` keeps company provenance, role metadata, connector roadmap and test cases separate from `definition`, which uses the existing strict Agent Studio schema. The 26 individual files contain only that importable definition. Draft templates are not signed model releases or marketplace publications.

All connector roadmap entries are NOT CONNECTED. Current executable grants are repository reads only. The implementation role may propose edits for human review; no role executes external writes, commits, ticket updates, releases or approvals.

Suggested catalogue lifecycle: draft → evidence-backed tests → independent review → publication through an implemented release contract → workspace installation. Only the draft pack and existing import workflow are provided here. No new release contract or marketplace backend is claimed.

## Suggested first demonstration

Requirements analyst → Architecture analyst → Implementation agent → Code reviewer → Agent evaluation reviewer → Release readiness reviewer → Delivery coordinator.

Supply a small synthetic project brief and repository, then review each handoff. Record real model identity, reported tokens, tool calls and elapsed time. A delivery ticket remains a draft until a separately authorized connector exists.

## Workspace installation

Open Agent marketplace in the app. An admin can add the pack or individual agents
into the selected workspace, then configure models and assign stages in Agent
Studio. Reinstalling preserves the workspace's edited copies. The 30-agent
workspace limit still applies. Installation does not execute agents, approve a
release, grant external connector access, or replace workflow stages.

Local mode saves separate workspace records on this computer and gives its owner
access to those workspaces. It is not a hosted company tenancy service. Managed
sign-in uses administrator-configured workspace memberships; company provisioning,
organization enrollment and cloud deployment are not included in this example.
